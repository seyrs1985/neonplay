# Tile Rush (tile-rush)

> 一句话卖点：**羊了个羊的干净网页版**——层叠牌堆点 3 张同款进托盘消除，7 格托盘撑住别爆，每天全球同一副"构造保证可解"的牌，无广告无体力。

- **缝合来源**：Tile Match/羊了个羊（三消托盘核心循环）× 麻将层叠牌堆（层叠遮挡的可访问性谜题）× 每日种子（日期哈希构造牌局，全球同题）
- **目标玩家**：Tile Match/羊了个羊 手游难民（被体力墙和插屏广告劝退的人）；麻将连连看/Onet 老玩家；通勤碎片时间人群
- **单局时长**：2-5 分钟/局；无限模式（种子随机）+ 每日同题

## 〇、差异化红线回答（LESSONS.md 第 8 条）

**"比 Google 搜索前 3 名多做了什么？"**——搜 "tile match game online"：品类 App 端巨大且常青（[Tile Explorer 位列 AppBrain 史上最多下载安卓解谜 Top20](https://www.appbrain.com/apps/most-downloaded/puzzle)，Tile Match/Zen Blossom/Tile Club/Tile Connect 克隆林立），**但 web 端干净供给与"每日同题"双双空白**（本轮调研搜索引擎明确提示无 web 克隆/每日模式对应结果）。本作：

1. **干净网页版**——App 端靠插屏广告+体力墙收割（玩 5 局看 6 个广告），本作零广告零体力、免登录、375×667 手机竖屏优先。→ 满足红线"解决 Reddit 上有人抱怨找不到好方案的问题"（品类诉求与 nonogram/idle 案例同源：无广告+无体力）。
2. **构造法可解性保证**——牌局由"逆序构造算法"生成：**每一局都数学上保证可解**（见二节），每日同题可与朋友比时间；App 克隆的随机发牌经常天然死局。→ 满足红线"组合两个已有玩法"（三消托盘 × 层叠牌堆，即羊了个羊已被验证的公式，web 端首次供给+确定性发牌升级）。
3. **留存五件套自带**——每日牌局+连胜（羊了个羊现象级爆款的原始引擎就是"每日一关"文化）+段位+分享卡，全部 localStorage 静态实现。
4. **与站内 Neon Pop 的查重边界**：Neon Pop=点 2+ 相连同色块（连通消除，无托盘无层叠）；本作=托盘三消+层叠可访问性，玩法族谱不同。

## 一、调研依据（2026-09-13）

### 热门拆解（含留存机制）
| 游戏 | 核心循环 | **留存机制** | 借鉴→本土化 |
|---|---|---|---|
| **Tile Match / Tile Explorer 系**（App 品类头部） | 点牌进托盘→3 同消除→清板 | 线性关卡+体力墙+插屏（留存靠关卡数堆量） | 保留托盘三消手感；用"每日同题"替代体力墙，用段位替代关卡数 |
| **羊了个羊**（2022 中文现象级） | 同上+两层叠牌+道具 | **每日一关**（全场同题，第二关地狱难度）+分享"我过了没"社交话题 | 每日同题文化原样移植；难度曲线改成构造可解的"难而公平" |
| **麻将连连看/Onet**（老牌层叠消除） | 层叠找可访问对 | 无 | 层叠遮挡的可访问性判定与视觉语言 |

### 需求与供给判断
- 品类热度：Tile Explorer 级下载量+2026 年仍在投新素材（Tile Connect "best in 2026" 广告），需求无需教育。
- 供给断层：免费干净版全在 App（靠广告变现的免费=重广告），web 端多为低质换皮站；"每日全球同题"在该品类 web 端为空白——而本站已有三款游戏验证日期种子流水线（brickstorm-daily/Alchemy/Nonogram）。
- 用户原声（品类通用痛点，与站内已验证案例同构）：无广告、无体力、卡关公平。

### 同构分析（饱和度）
- App 端：卷关卡数（7000+关）与主题皮肤；数值上靠体力墙逼看广告。
- web 端：低质换皮站为主，无确定性发牌、无每日、无段位、手机竖屏适配差。
- "构造可解"是竞品做不到的硬承诺（随机发牌无法保证），也是每日同题可比较性的前提。

### 异构分析（NeonPlay 现有 17 款的缺口）
现状四类分区：🎮街机动作 6、🧩益智解谜 6、🐝词与逻辑 4、💫放置挂机 1；pending 另有反应类（reflex-rush）、体育类（neon-hoops）。
- **缺口：层叠空间消除=0 款**——益智系全是平铺网格（2048/扫雷/block-blast/nonogram），无"上下遮挡"的空间维度；本作引入 Z 轴，操作光谱补全。
- 受众：Tile Match 品类主力（25-45 女性、通勤人群）与站内现有用户重叠低；羊了个羊话题性自带传播。
- 时长结构：2-5 分钟局+失败即重开，填满碎片场景。

### 组合为何成立
- 托盘三消的"收集欲"×层叠牌堆的"空间推理"——羊了个羊已验证二者咬合（托盘压力逼你规划"先动哪张上层牌"）。
- 构造算法让"随机性"与"公平性"共存：每天牌不同但都有解，分享语境从"这游戏纯坑"变成"你多少秒过的"。
- DOM 实现 Z 轴天然（z-index+浏览器点击命中上层牌），比 canvas 层叠命中测试省一个数量级代码。

## 二、玩法设计

### 规则（MVP 共 7 条）
1. 牌面 emoji（12 种池：🍉🍇🥑🌶️🍄🐟⚡💡🌙⭐🍩🎧）；牌局 = N 个三元组（同面 3 张）分布在**层叠牌堆**上，层间可部分遮挡，同层不重叠。
2. 点击**最上层可见**牌→飞入底部托盘（7 格）；托盘内凑满 3 同面→消除（爆裂动画）；托盘 7 格满且未凑三→**败局**（可重开，牌局不变——同题重试）。
3. 全部牌消除（板上+托盘清空）→**通关**，按用时与道具计分。
4. 道具每局各 1 次：**移出**（托盘前 3 张送回牌面新顶层位置）/**洗牌**（剩余牌面重排——保留各面计数，可能产生死局，属品类原味风险）。
5. **构造可解（核心承诺）**：牌局由逆序构造生成——设移除顺序为三元组 T1→T2→…→Tk（T1 最先移除），放置时按 k→1 逆序：Ti 的 3 张放在第 (k−i+1) 层随机空位（同层互不重叠）。不变量：移除 Ti 时其上方只可能有 Tj（j<i）的牌，而届时已移除——**按顺序必可解**。板上牌面永远与构造三元组一致（无多余牌）。
6. 模式：**无限模式**（mulberry32 随机种子，参数随难度档：休闲 k=12 层≤6 / 标准 k=18 层≤12 / 挑战 k=24 层≤18）/**每日牌局**（`mulberry32(YYYYMMDD)` 固定参数种子，全球同题，当日通关打戳，可反复挑战刷时间）。
7. 计分：`score = 500 + max(0, 900 − 秒数×5) + 未用道具×150`；失败重开不重置每日尝试次数。

### 段位阶梯（按单局分）
| 段位 | 分数 | | 段位 | 分数 |
|---|---|---|---|---|
| 🏆 传奇 | ≥2100 | | 🟡 黄金 | 900-1199 |
| 🥇 大师 | 1800-2099 | | ⚪ 白银 | 600-899 |
| 💎 钻石 | 1500-1799 | | 🟤 青铜 | <600 |
| 🥈 白金 | 1200-1499 | | | |

*注：阈值按"标准档 18 三元组、3-4 分钟通关、用 1 道具"估锚（≈1,150 分），开发实测后允许 ±20% 微调，段位结构不动。*

### 核心循环（4 步）
1. **扫面**：在层叠堆里找"现在就能动"的三张同面（上层压着的要先用道具牌顶开逻辑）。
2. **取舍**：托盘 7 格是稀缺资源——拿这张会不会堵死下一张？规划移除序。
3. **消除**：三张聚拢爆裂，牌堆露出新可动面，节奏爽点。
4. **收官/翻车**：清板通关冲时间分，或托盘爆满差一格——分享"差 2 格败北"与"3:12 通关"都是社交货币。

### 操作方案
| 端 | 操作 |
|---|---|
| 触屏 | 点最上层可见牌→飞入托盘；浏览器 z-index 命中天然只响应可见部分 |
| 鼠标 | 同触屏 |
| 键盘 | 方向键移动焦点（仅层叠面上"当前可点"牌循环）→Enter 拾取；1=移出道具 2=洗牌道具 |

### 美术方向（霓虹色板）
- 底 `#0a0a18` 深空；牌=圆角方块玻璃拟态+emoji 大字，未遮挡牌面青 `#00e5ff` 描边微光，被遮挡牌压暗 40%（可访问性可视化——比竞品多一层"哪些能动"的读懂性）。
- 托盘=底部 7 格品红 `#ff2d95` 描边槽位，凑三消除=三牌聚拢挤压+粒子爆裂+金色 `#ffd54a` 飘字；托盘 ≥5 格时槽位呼吸红光警告。
- 层叠=层间阴影+半格错位制造高度感；通关=全牌堆 confetti+用时大字翻滚；败局=托盘红闪+震屏。
- 道具按钮=右上角圆形玻璃钮（1 次/局，用后灰化），键盘 1/2 快捷键标注。

## 六、MVP 范围（开发 Agent 一轮 ≤15 分钟，含留存基线）

**做**：
- 结构仿站内惯例：`index.html + game/style.css + game/js/main.js + game/js/game.js`；**DOM 层叠**（绝对定位+z-index，浏览器原生命中上层可见区）。
- 构造算法按二节伪代码（逆序放置+同层不重叠+不变量），三难度档参数；**QA 断言构造不变量**（三元组计数、同层不重叠、按构造序模拟可清空）。
- 核心玩法：点牌入托盘（飞行动画）、3 消判定、7 格败局、双道具（移出/洗牌各 1）、计时与计分、通关/败局面板。
- **留存基线（模板硬性要求）**：best/Top10/weekly/daily/streak（月度补签卡）/stats 六键按清单，10s 自动存+结算即存；分享卡 canvas+Web Share API→剪贴板降级；段位+差值展示。
- 动效：消除聚拢爆裂、托盘告警呼吸、败局震屏、通关 confetti；中英 i18n（np_core）；`__qaState/__qa`（含 `__qa.solveStep()` 按构造序自动移除一组，供 QA 通关断言）。
- 落地页：VideoGame/FAQPage schema + 4 FAQ + 推荐位。

**不做（明确砍掉）**：音效、牌面主题包、连通型道具（撤销单张）、关卡进度图、ghost 线、小任务、zen 模式。
**超时降级顺序**：先砍洗牌道具（保留移出）→ 再砍 weekly 榜 → 三难度档降为单一"标准"参数 → 构造算法+每日+streak 不可砍。

## 八、验收标准

1. 线上 `/tile-rush/` HTTP 200；375×667 游戏框首屏 58vh（一票否决项）；无控制台报错。
2. **玩法验证红线（LESSONS 第 9 条）**：qa_playtest 用 `__qa.solveStep()` 按构造序移除 3 组→断言托盘 3 消与板上计数递减；循环至清板→断言通关面板与用时；再用错误序塞满托盘→断言败局面板；全程 `window.onerror` 零报错。纯布局 pass 不算可玩。
