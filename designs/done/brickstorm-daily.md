# Brickstorm 每日挑战（brickstorm-daily）

> 一句话卖点：**每天全场同一张"题"**——固定种子波次，全球玩家同一榜单比波次比分数，把 Brickstorm 从"一次性体验"变成"每天回来"的习惯。

- **类型**：现有游戏功能增强（Brickstorm，2026-09-11 已上线 /brickstorm/）
- **来源**：brickstorm.md 原设计文档遗留 P2 项（"每日挑战：固定种子，全站同题"）；本轮由运营决策直接下单——复访价值是当前最便宜的收益杠杆（DAU 翻倍=广告库存翻倍，比拉新便宜一个数量级）

## 调研依据

- Wordle 模式验证：固定每日一题 + 可分享结果 = 极强回访（NYT 采购案例，公开事实）
- brickstorm.md 自身遗留项：`designs/done/brickstorm.md` 商业化一节"每日挑战（固定种子，全站同题）列为 P2"
- 站内现状：9 款游戏全部无跨天机制，无任何"明天再来"的理由

## 同构分析（饱和度）

网页小游戏站带每日挑战的比例低；做的话通常是"每日换关卡"手工内容（有生产瓶颈）。本站走**程序化固定种子**路线，零内容生产成本，与 Agent 流水线天然匹配。

## 异构分析（与站内互补）

站内 9 款均为单局即弃，无 streak/每日机制；Brickstorm 是唯一具备"波次生成+构筑随机性"的游戏，最适合种子化——同种子下波次序列一致，成绩天然可比。

## 功能骨架（MVP）

1. **入口**：开始面板加两个按钮 `CLASSIC` / `DAILY <日期>`（触屏目标 ≥44px，英文文案）
2. **种子**：`mulberry32(seed)`，seed = 当日日期字符串哈希（如 `YYYY-MM-DD`）。种子只注入**波次生成器**（砖阵构成/HP 浮动），玩家操作与物理不种子化。普通模式必须保持原有 `Math.random` 行为不变
3. **成绩**：每日最佳独立存储，localStorage 键 `brickstorm_daily_best_<YYYY-MM-DD>`，结算面板展示 `Today's Best`；原 `brickstorm_best` 不受影响
4. **降级方案（若核心逻辑无干净 RNG 注入点）**：改为"每日修饰词"模式——按日期从固定表轮换全局变体（如 Monday: 球速+15%、砖HP+1；Tuesday: 多球初始+1…），同样实现每日同题，改动更小
5. **P2 不做**：好友分享卡片、全球排行（无后端）

## 双端操作

- 触屏：两按钮 ≥44px；游戏内操作沿用现有拖动方案
- 桌面：`C`/`D` 快捷键可选

## 美术方向

沿用 Brickstorm 现有霓虹规范（#0a0a18 底、cyan/violet/pink）；DAILY 按钮用金色 #ffd54a 描边以示"今日限定"。

## 商业化与留存钩子

- 每日挑战本身就是留存钩子；结算页 `Come back tomorrow for a new board` 文案
- 广告位照旧，不新增

## SEO 关键词簇

次要（本方案价值在留存不在拉新）：`daily challenge browser game`、`brick breaker daily puzzle`

## 验收标准

- 同一天两次进入 DAILY 模式，前 3 波砖阵构成一致；CLASSIC 模式行为与改动前一致
- 375×667 视口：开始面板两按钮首屏可见、≥44px、无横向滚动
- 游戏内新增文案全英文，且集中进内嵌 `var L={en:{...},zh:{...}}` 字典结构（用 `np_lang` 键），预留 i18n 轮
- 无控制台报错；移动端首屏验收通过后才可部署
